GameSplat: Optimizing Gaussian Splats for Video Game Scenes

Team Members: Jonathan Cao, Laurier Ke, Justin Lee, Jameson Liu
Proposal webpage

Summary

GameSplat will reconstruct a 3D Gaussian splat from video game footage. We will develop three connected parts of the pipeline: COLMAP-based pose estimation and trajectory selection, automated UI masking, and a repeated texture prior for refinement. The output will be a Splatfacto model, an exported PLY, and a flythrough video.

Problem Description

Gaussian splatting typically starts with views of a static scene along with known extrinsics and intrinsics. Gameplay video may provide only images without camera poses, so we must rely on Structure-from-Motion via COLMAP.

Unlike real-world footage, video game footage contains fixed UI elements, including reticles and inventory bars. Player arms, weapons, and tools also move separately from the world. Treating these as scene content creates floaters and can severely damage COLMAP feature matching, which motivates excluding them as a preprocessing step.

Video games also contain repeated textures and materials, which create ambiguity in pose estimation. While repeated textures can mess with COLMAP, they are also an advantage during reconstruction because repeated material is a useful prior. For example, a nearby copy of an object may show the same material more clearly than a distant one. During training, the nearby observation can constrain the shared texture of the distant object; when a held-out view contains that distant object, this shared estimate should generalize better than fitting its limited observations independently.

Our pipeline is: gameplay video → frame extraction and global screen-space masks → masked COLMAP pose recovery and trajectory selection → stock Splatfacto Gaussian splat training → repeated-material texture refinement → PLY, held-out renders, and flythrough.

Masking will use screen-space techniques such as edge detection and color persistence, along with consistent pixel disagreement during an initial reconstruction pass. A broad COLMAP pass will select the longest temporally smooth pose segment, then a denser pass will reconstruct it. The texture stage will jointly refine repeated material patches while retaining a standard Gaussian splat PLY. We will judge it on held-out views and patches, rather than training loss alone.

Goals and Deliverables

What We Plan to Deliver

  1. A pipeline/codebase for reconstructing gameplay scenes. Our results will be reproducible using this code.
  2. A comparison between different masking techniques. We will show masks from our pipeline alongside human-labeled masks and a no-mask ablation, then measure downstream pose-estimation and reconstruction quality.
  3. A comparison of coarse-to-fine and single-pass COLMAP. We will compare their selected trajectories and measure downstream reconstruction quality.
  4. A comparison of texture-refinement techniques. We will compare methods for refining repeated textures, including optimizing geometry and color versus optimizing color alone.
  5. A final paper and generated artifacts. The results will include masks, COLMAP trajectory paths, close-up texture-refinement comparisons, and overall reconstruction images, PLYs, and flythroughs.

What We Hope to Deliver

  1. A comprehensive hyperparameter sweep for the above techniques. Each pipeline stage has parameters that influence its behavior; for example, the masking algorithm will have a configurable tolerance for RGB shifts. If time permits, we will evaluate how varying parameters affects performance.
  2. An evaluation of pipeline performance across different video games. We plan to start with Minecraft and try a few other games if time permits.

Questions and Evaluation

  1. Does automatic UI masking consistently match manually created masks across multiple inputs?
  2. How effective is pixel disagreement with the scene at identifying UI elements?
  3. Does coarse-to-fine trajectory selection improve pose-estimation stability or worsen view coverage?
  4. Can shared texture optimization improve validation performance without hurting training performance?

We will have different measurements of quality for each part of the pipeline. For masking, we will measure the percentage of the screen masked out and the percentage of ground truth UI incorrectly left unmasked. For COLMAP, we will measure rotation and translation changes between consecutive frames and COLMAP's reported reprojection error. For Splatfacto reconstruction, we will measure PSNR, SSIM, and mean RGB error on held-out validation images, and inspect training curves.

Schedule

Week 1: Baseline Pipeline and Evaluation

  • Get a basic pipeline working with stock COLMAP and Splatfacto.
  • Run on simple inputs with UI hidden.
  • Build scaffolding for evaluation.

Week 2: Automatic Masking and COLMAP Trajectory Selection

  • Implement screen-space masking techniques and the disagreement measurement workflow.
  • Test masking techniques against the baseline.
  • Implement coarse-to-fine COLMAP passes.
  • Test COLMAP improvements against the baseline.

Week 3: Texture Refinement

  • Implement automatic detection of shared and repeated textures.
  • Implement techniques to jointly optimize identified textures.
  • Compare techniques against the baseline.

Week 4: Experiments and Presentation

  • Run configuration combinations at several seeds and collect results.
  • Finalize code deliverables and artifacts.
  • Write the final paper and prepare the final presentation/demo.
